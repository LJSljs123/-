# 密营 · 工程骨架

东北抗联十四年史料的可核查重建 — 2026 数媒竞赛（红色之旅 追梦铸魂）

## 这个作品在做什么

不是 VR 纪念馆，也不是把史料铺在地图上的"时空漫游"。**它审的是"记载"，不是历史。**

红色展馆几十年都在展示结论——抗联苦战十四年、杨靖宇壮烈殉国。这些结论当然成立，但结论背后的推理链条一直被藏起来。历史学本来是「证据 → 推断 → 结论」，展陈只给你最后一步。

密营把中间两步摊开：

- 每条记载都能追溯到一本书、一页纸、一句原文
- 三个 agent 对同一条史实做结构化质证，**各自的权限被硬性限制**
- 解决不了的分歧登记为**悬案**，写明缺什么材料才能定谳
- 「不知道」是一等公民，不是需要被掩盖的缺陷

一句话：别人做"讲给你听"，我们做"给你看证据是怎么站住、又是在哪里站不住的"。

### 三个 agent，三条硬边界

| Agent | 职责 | 硬规则 |
|---|---|---|
| **拆解** | 把命题拆成原子断言，逐项判定确定性 | 只拆解，不判断 |
| **辑录** | 从库内检索原文，逐字照录 | **只引用，不生成**——找不到就说找不到 |
| **质证** | 挑时点错位、转引同源、孤证、约数当精确值 | 只质疑，不下结论 |
| **存疑** | 登记悬案，给出证据支持的最保守结论 | 解决不了就登记，不硬给答案 |

第三条最关键：**"史实存疑"和"库内证据不足"是两回事**。前者说的是历史本身不确定，后者说的是我们还没收集够。把两者混为一谈，是数字人文项目最常见的自欺。系统对这两类给不同的结案状态。

## 数据真实性红线（最重要）

1. **无来源不入库。** `sources` 为空的事件一律拒绝，脚本会报错。
2. **原文摘录不得改写。** `quote` 字段是史料原话，不是转述。
3. **不确定就标 null，不猜。** 坐标只知到县就填县质心，`precision` 写 `county`。
4. **伤亡数字有冲突就保留冲突**，不取平均、不选一个"看起来合理"的。
5. **LLM 只做抽取辅助，不做生成。** 抽取结果必须人工对照原文复核。
6. `data/demo/_demo_synthetic.json` 是占位数据，**任何情况下不得进入提交材料**。

### 两层数据

- **遗址层**：34 处，作为独立数据层保留。来源为国务院《关于公布第 1–4 批国家级抗战纪念设施、遗址名录的通知》，名称与地址为名录原文，可信度 A。
- **事件层**：39 条，来自 16 个来源，其中 29 条有 2 家以上来源对位。20 条可定位到县/乡镇，19 条只到省或跨省，**不编造坐标**。

### 负证据（provenance）—— 这一版最重要的改动

问题：说「这条只有一处记载」，评委会问一句就废掉——**你找过吗？**

如果只抄了一篇报纸，那 92% 单一来源不是发现，是采样方式的结果。所以每条结论都要记下检索过程：

```json
"provenance": {
  "depth": "deep",
  "on": "2026-10-17",
  "probes": [
    {"q": "赵尚志 1942年2月 牺牲 梧桐河 日期", "n": 5,
     "indep": ["赵尚志纪念馆", "侵华日军南京大屠杀遇难同胞纪念馆"],
     "deriv": 3,
     "note": "两家纪念馆均载 2月12日，与年表、本报四方一致"}
  ],
  "not_searched": ["《赵尚志传》纸本（未获取）", "黑龙江省档案馆（闭架）"]
}
```

三个设计要点：

**1. 独立记载与转抄分开计。** `indep` 只收真正独立的记载，百科、文库、自媒体一律计入 `deriv`。检索一条史实，返回 5 条结果全是转抄，和返回 2 家纪念馆，是完全不同的事——混在一起算，就是在虚报证据。

**2. 必须写 `not_searched`。** 没查的东西不写，就退化成默证（argument from silence）——"没找到"被偷换成"不存在"。默证在史学上不能当证据。把闭架档案、未获取的纸本列出来，读者才知道这个"没有"的边界在哪。

**3. 深度分三档，不装。** `deep`（逐库多轮）、`shallow`（一次聚合检索）、`none`（尚未逐条检索）。前端把 `none` 直接标出来："尚未逐条检索，此处不冒充已查"。

校验器会拦两种作弊：把已入库来源又算作"独立命中"（重复计票）；检索到了独立记载却仍只留一条来源、且不写理由。

**两轮检索的实际结果**（39 条结论，2026-10-17 检索）：

| 指标 | 初版 | 一轮检索后 | 二轮检索后（当前） |
|---|---|---|---|
| 来源数 | 6 | 10 | **16** |
| 多源结论 | 3 | 17 | **29** |
| 单一支撑 | 36（92%） | 22（56%） | **10（26%）** |
| 抽掉辽宁日报崩塌率 | 92% | 56% | **26%** |
| 检索深度 | 无记录 | 深 9 / 浅 11 / 未查 19 | **深 20 / 浅 19 / 未查 0** |

关键不是数字变好看，是数字**开始可信**。补进一份独立的《东北抗联大事记》年表后，崩塌率从 92% 降到 56%；再把年表 1932–1945 十一个年份全文抓下来逐条对位、并补进中央档案馆档案展与三家黑龙江机构后，崩塌率降到 26%——这说明扩来源确实有效；剩下的 26% 是真的补不上，不是没去找。

而且那份年表**独占 0 条**：它确认了 25 条，却没有提供任何一条独家信息。第二个独立来源的价值是「确认」，不是「补充」——这一点只有把 `exclusive` 与 `count` 分开算才看得见。

### 二轮检索的新发现（年表 1932–1945 全文对位）

把《东北抗联大事记》十一个年份页全部抓下来逐条对位，19 条未查条目全部落位：

- **日期精度升级 5 条**：六届六中全会慰问电（11月→11月5日）、南满省委会议（10月→10月1日，补出地点桦甸头道溜河）、汪雅臣牺牲（1月→1月29日，补出五常石头亮子）、告东北民众书（7月→7月11日）、统一建制宣言（三源逐日一致 2月20日）。
- **新登记一处整月级日期冲突**：抗日同盟军收复多伦，辽宁日报记 6 月，国家级纪念设施"察哈尔抗战遗址"认定 **1933 年 7 月 12 日**（吉鸿昌率部五昼夜激战）——本报的 6 月无法交叉验证。
- **三家机构级独立记载**：《告满洲各地义勇军书》被黑龙江省文旅厅、东北烈士纪念馆、黑龙江省档案馆分别记载，日期一致；东北烈士纪念馆藏原件刻印"1931年3月31日"，馆方考订为笔误——原件笔误与报载日期的差异本身就是考据素材。
- **两处负证据补齐**：救国会 5 军区改编、杨靖宇桓仁收编，在抗联年表与公开检索中均无独立记载。另注意《东北抗联大事记》只收中共领导的东北抗日武装——热河、长城、多伦等关内战线事件在该年表无载属收录范围所限，**不算负证据**，检索记录里如实注记。

### 检索本身得出的一个结论

39 条里，被反复记载的是杨靖宇、赵尚志、邓铁梅——都有纪念馆、中国军网、央视的独立报道。而江桥抗战、东北民众抗日救国会、绿林改编这些同等重要的事件，公开检索 5 条结果全是百科与自媒体的互相转抄，**一家独立记载都没有**。

**独立记载的密度，取决于这件事是否被纪念，不取决于它是否重要。**

这不是抒情，是检索记录算出来的。也正因如此，"单一支撑"在这个库里不是缺陷统计，而是记忆分布的测量。

### 数值主张（measures）——冲突检测的核心

史料分歧最常见的形态不是"两条事件记录"，而是**同一条事实的不同来源给出不同数字**。为"抗联鼎盛兵力"伪造第二条事件来凑冲突，等于造假。

所以数值是**来源级**的：每个数字都记着出自哪本书哪一页。

```json
"measures": [
  {"name": "总兵力", "value": 30000, "unit": "人",
   "source": "人民日报《弘扬历久弥新的东北抗联精神》", "page": "2021-10-28"},
  {"name": "总兵力", "value": 45000, "unit": "人",
   "source": "国家图书馆《抗联简史》（引孔令波《军事历史》1986年第4期）"}
]
```

引擎先按数值归并来源，再对不同数值出报告——两个来源都说 50 万只算一个取值，不会报成两处分歧。

**当前已入库的真实分歧（全部照抄原文，未做任何换算）**

| 冲突组 | 分歧 | 记载一 | 记载二 | 相对差 |
|---|---|---|---|---|
| `cg_kanglian_bingli` | 抗联鼎盛时期总兵力 | 3 万余人（人民日报 2021-10-28） | 四万五千余人（国图《抗联简史》，引《军事历史》1986-4） | 33% |
| `cg_yiyongjun_renshu` | 义勇军鼎盛时期总人数 | 约 50 万（抗日战争纪念网、国图《抗联简史》） | 30 万（莆田市博物馆） | 40% |

第二组尤其值得注意：抗日战争纪念网原文写作"总人数约50万（**一说30万**）"——史料自己就承认了分歧。

另有一处**精度差异而非数值分歧**：教导旅成立时间，彭施鲁记"1942年8月1日"、辽宁日报记"8月"、国图《抗联简史》记"1942年秋"。系统按最精确记载定为 8 月，三句原文并列保留在证据卡里，不合并、不改写。

```bash

python src/build_structures.py                                          # → web/structures.js
python src/build_web.py data/curated/events.json data/curated/conflicts.json
# 然后双击 web/index.html（承重结构）；卷宗视图在 web/dossier.html
```

`merge_provenance.py` 可重复执行：来源按书名去重，不会因为跑两次而入两遍。

数据用 `<script src="cases.js">` / `<script src="data.js">` 注入，不用 fetch，因此 `file://` 协议下也能加载，双击即可运行。

### 审问案的生成逻辑（`src/build_cases.py`）

**不是写死的文案，是规则生成。** 三类案子：

| 类型 | 触发条件 | 结案状态 |
|---|---|---|
| `dispute` 多源分歧 | 同一数量项在同一事件下出现 ≥2 个不同取值 | 悬案 · 无法定谳 |
| `single` 孤证 | 只有 1 条来源的牺牲事件 | 库内证据不足 |
| （预留）`settled` | 多源一致且有一手档案 | 可以定谳 |

质证规则 R1–R7，全部可解释、可复算：

| 规则 | 判定 |
|---|---|
| R1 时点无统一定义 | 原文含「鼎盛/前后/时期」等模糊语汇 |
| R2 转引而非独立记载 | 来源书名含「引」，两条记载可能只有一票 |
| R3 库内无一手档案 | 无 A 级来源，只能证「有人这样写过」 |
| R4 数值离散超出容差 | 相对差 ≥25% 判高 |
| R5 孤证 | 仅 1 条来源 |
| R6 约数被当作精确值 | 原文含「约/余/近/逾」 |
| R7 史料自认存在异说 | 原文含「一说」 |

R4 与 R6 会同时出现且**不互相取消**——R4 算出百分比，R6 指出这个百分比建立在约数换算上只能看量级。系统把自己的计算局限也写进质证里。

### 界面能力

**承重结构（`index.html`，主入口）**

把整个史料库摊成一张受力图：**上层的每条结论，都由下层的来源托着。**

- **芦苇**：一条结论一根。单源的红、多源的（更粗更高）金色。从基线向上长，高度即"能站多稳"
- **来源柱**：柱宽 ∝ 它支撑的结论数，柱内每道刻痕就是一条被它托着的结论。宽度差异一眼可见 95% / 3% / 1% 的量级差
- **悬停预演**：鼠标停在柱上，该来源的全部支撑线亮起，顶部实时算出「抽掉它 → 失去 N 条」。**不用点，先给你看后果**
- **点击抽离**：抽掉的来源变虚线框，它托着的结论整片伏倒（左右交错，像被风压过的芦苇），只剩还有别的来源托着的立着
- **连带降级**：底部同时报出哪些审问案失去核心论据——承重结构和卷宗视图是同一套数据，不是两张皮
- **图注数字不手填**：`10 / 39`、`26%`、`56 组检索` 全部由 `build_structures.py` 算出后注入
- **检索记录随点随看**：悬停任一结论，浮层里写明查了几组关键词、几家独立记载、几条转抄、哪些库没查

为什么是这个形态：红色展馆几十年都在展示结论。承重结构不展示结论，它展示**结论靠什么站着、抽掉哪一根会塌**。这是"可核查"唯一诚实的可视化方式——核查的本质就是问"如果这条记载是错的，还有别的什么能撑住它"。

**卷宗视图（`dossier.html`，副视图）**

- 四段式卷宗：拆解 → 辑录 → 质证 → 存疑，逐条浮现，让推理过程有时间性
- 断言表：主体/时点/地点/数值逐项标注「确定 / 较粗 / 模糊 / 约数」
- 证据卡：来源 + 页码 + 可信度等级 + 原文（斜体）+ 数值（金色等宽）
- 质证项：朱红竖线，R 编号 + 严重度
- 悬案印章：旋转的朱红方章，压在结案框右上角
- 键盘：空格跳过动画，←→ 换案

### 坐标说明

`data/curated/sites.json` 中的坐标为**县级质心估计值**，`precision` 标为 `county`。事件层的 `site` 精度必须是真实坐标，不得用县质心冒充遗址位置。本版前端不使用地图，坐标仅作为史料属性保留在数据层。

### 冲突检测的判定逻辑

冲突分两种形态，引擎分别处理：

- **within（事件内）**：一条事件内部，不同来源对同一数量项给出不同数值。这是史料分歧最常见的形态。
- **between（事件间）**：同一 `conflict_group` 的两条事件记录，字段不一致。

| 字段 | 形态 | 判定 | 严重度 |
|---|---|---|---|
| `measures`（同名数量项） | within / between | 相对差 ≥25% 高，≥10% 中，其余低 | 可调 |
| `date.start` | between | 月份差 ≥6 判高，<6 判低 | 可调 |
| `place.modern` | between | 今地名不同即判高 | 固定 |
| `casualties.our` | between | 相对差 ≥50% 判高 | 可调 |

### 置信度公式

```
置信度 = 最高来源等级权重(A=1.0/B=0.7/C=0.45)
       + 0.08 × (来源数−1，最多+0.24)     # 多源互证加分
       − 0.12 × 高严重度冲突数             # 冲突扣分
下限 0.05
```

### 承重结构分析（`src/build_structures.py`）

冲突检测回答"哪里对不上"，承重结构回答**"对不上的时候，还有没有别的东西撑得住"**。

把来源 → 结论的支撑关系建成二部图，算三件事：

| 指标 | 定义 | 当前值 |
|---|---|---|
| 单一支撑 | 只有 1 个来源支撑的结论 | 10 / 39（26%） |
| 单点故障 | **独占** ≥50% 的结论（抽掉它就塌一半） | 1 个（辽宁日报，独占面 26%） |
| 崩塌率 | 抽掉某来源后，失去全部依据的结论占比 | 抽掉辽宁日报 → 26% |
| 纯冗余来源 | 支撑面很宽但独占面为 0 | 抗战纪念网（支撑 25 条，独占 0 条） |

来源按「出版社 / 机构名」归并，不按书名全串归并——否则同一本书的转引版本会被拆成两根柱子，把一票算成两票。

**单点故障判在"独占"上，不是"支撑"上。** 一个来源可以支撑 95% 的结论却只独占 26%——抽掉它塌四分之一，不是塌全部。用支撑面判会把冗余误报成脆弱：抗战纪念网支撑 64% 的结论，独占 0 条，抽掉它一条都不塌，那不是单点故障，那是备份。

这三个数字不是修辞。它们是这个库**当前的承重能力**，会随入库来源增加而变化。这也是把数据层和展示层分开的原因：前端不写死任何数字，全部由分析脚本注入。
