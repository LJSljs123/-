# 《密营》审查与接手记录

更新：2026-10-18

## 当前状态

作品主线是东北抗联史料的可核查重建，前端由 2D 承重结构、灯下卷宗和 3D 燎原组成。工程可本地静态打开，事件、冲突、卷宗和结构图均可由仓库脚本重建。

说明：下列“红色优先雪原”是较早一轮的历史记录，现行口径已调整为冷林、深木、灰绿布料和克制琥珀光。逐项改进与本项目剩余验收门槛见 [《项目全量审查与升级路线》](项目全量审查与升级路线_20261018.md)。

## 2026-10-18 后续复核：3D、WebXR 与移动端

- 3D 主视觉改为红色优先的雪原与程序化林海；修正事件灯火、来源烽燧贴地，降低地形遮挡，并按名录经纬关系放置 34 个带精度提示的地理锚点。
- 3D 脚本改为独立的 `web/sanctuary.js`，使用 Three.js `setAnimationLoop` 兼容沉浸式渲染；新增自动导览、手机方向环视（3DoF）及 WebXR 双目、手柄指向选取、地面瞬移和世界空间证据卡。
- 修复风雪试验复原后不能再次结算；把程斌与杨靖宇相关记载改为单独并置，虚线不计入来源支撑、因果判断或熄灭统计。
- 2D 承重结构增加手机双向滚动查看；卷宗页在手机上改为横向案卷导航，并可直接切换到 3D。
- Chromium 浏览器检查：3D 页面无 JavaScript 错误，风雪试验连续两次均能结算；2D 与卷宗页已复查移动断点。仍有 Three.js r150 UMD 构建的上游弃用警告；为保持静态离线兼容暂未升级。WebXR 在本机浏览器中只验证能力检测与不支持提示，没有实体头显可做 6DoF 真机验收。

## 2026-10-18 后续迭代：故事、概念图与被服厂场景

- 视觉口径修正：本项目的“红色”指抗日战争革命精神，不表示整屏红色滤镜。被服厂段落使用林木、旧木、灰绿布料、铁器和少量琥珀灯光；风雪仅作为其他历史场景的表现模式。
- 先按史料完成《针线与守望》八幕故事，再据此整理被服厂、匿名人物、缝纫机与道具的高细节提示词。日期、人员构成、机器、染布方法和结局链接到黑龙江省文化和旅游厅转载的《黑龙江日报》；未被文字材料确定的房屋布局、服装细节和人物长相均标为合成示意。
- 按提示词多轮生成并修订无雪密营环境图、被服工与战士转面、脚踏缝纫机参考图；移除了无史料支撑的战士袖章。参考图均作为栅格概念图，不伪称可直接用于 VR 的拓扑模型、贴图包或 GLB。
- 程序场景迭代发现并修复树实例留在原点、遮挡缝纫工的问题；修正相机近景半径被全局下限锁死、地面颜色按 sRGB 错误解释的问题，并调整移动端剧情卡位置。桌面与 390px 手机预览均无横向溢出，复原按钮可退出场景焦点。
- 自检：`node --check web/sanctuary.js` 与 `git diff --check` 通过；Chromium 桌面/手机预览无 JavaScript 错误，控制台仅见 Three.js r150 UMD 弃用警告。未进行实体头显测试，也未产出 Blender 高模、绑定动画或 GLB；程序几何仍属可运行的概念场景，不能表述为电影级最终角色资产。

## 2026-10-18 本轮升级：叙事入口、视觉层级与规则口径

- 3D 首页新增带 AI 艺术示意标记的开场图；默认雪原亮度、环境光、火光和地面光斑已收束，工厂院落增加林木密度并压暗地表材质。
- “针线与守望”改为独立 88 秒八幕故事漫游：可自动播放、暂停、拖动进度、上一幕/下一幕；主动拖动镜头或滚轮缩放时会暂停自动运镜；字幕可直达被服厂报道原文。
- 规则引擎的数值分歧案不再把主体、日期精度、地点精度和值状态混写成“确定”；README 已明确四个卷宗段落是规则生成的流程标签，不是运行中的 AI Agent。
- 浏览器桌面与 390px 手机视口已检查首屏、工厂故事卡、史料来源链接及章节状态；手机端无横向溢出。故事入口、自动推进、暂停、手动下一幕和复原均通过；控制台记录到 0 条应用 JavaScript 错误、1 条 Three.js r150 UMD 上游弃用警告。实体头显和性能基准仍未验证。

全量复核命令已通过：`conflicts.py`（66 条事件、0 项校验问题）、`build_cases.py`、`build_structures.py`、`build_web.py`、`verify_quotes.py`（35 条活动存档引文和 7/7 关键检查）、11 个 Python 源文件 AST 解析、13 个 JSON 文件解析及 `node --check web/sanctuary.js`。

本轮已修正：

- 8 个多来源案件原先都被标为“可以定谳”，即使没有一手档案。现标为“库内记载相合”，缺少档案依据时明确不定谳；将来只有满足一手来源条件的案件才进入 `settled`。
- 卷宗页原先把所有非分歧案显示为“孤证审查”。现按 `consistent`、`settled`、`dispute`、`single` 分别显示。
- 首页原先把动态单源数放在固定的 `/39` 后面。现从生成数据读取分子和分母。
- 来源链接原先会把外部网页称为“本地快照”。现区分本地快照与来源网页，并在有快照时提示哈希清单。
- 冰趟子引文已按本地快照更正；无对应文件的说明性路径和无法提取正文的抓取件不再作为可核查快照引用，原始说明和文件均保留。
- 存档核查器逐条验证活动引用的 HTML 哈希、字节数、manifest 对应关系、从已哈希的 HTML 重新提取正文并核对引文片段；下载器拒绝正文为空或过短的响应。
- 多来源统计统一按不同来源机构计数，当前为 55/66；置信度中的机构数加分按去重后的机构计算，并明确标注为启发式分值，不代表来源独立或概率。

## 交付顺序

1. **先锁材料口径**：确认报名系统要求、作品匿名范围、AI 与第三方资源声明字段、签署承诺书的负责人。
2. **先出主片脚本再录制**：15 秒内交代人物/事件、史料分歧和作品如何展示证据；全片建议控制在 3–5 分钟，优先保证旁白、字幕和证据可读。
3. **做提交副本**：静态页面、源码、数据、依赖许可、作品运行说明、评审截图和视频/PPT放入清晰目录；在干净目录离线打开 2D 与 3D 页面。
4. **完成验证材料**：邀请 3–5 位真实试用者记录任务完成情况和反馈；不补写或模拟用户数据。
5. **10 月 22 日前做提交演练**：逐项对照官网清单，核对匿名、文件可开、系统字段和上传结果；10 月 23 日 17:00 前提交。

### 视频开场建议（前 15 秒）

- **0–4 秒**：出现童长荣牺牲日期相差整月的具体分歧，字幕只写“记载相差一个月”。
- **4–10 秒**：并列展示年表、国防部和纪念馆的日期记载，鼠标打开引文和检索记录。
- **10–15 秒**：落到作品主张：“不替史料定案，把依据、分歧和证据边界展示出来。”

不要用 66/33 等指标或雪原空镜作为第一信息；先让评委知道要解决什么，再展示场景和系统。
