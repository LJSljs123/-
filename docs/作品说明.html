一、一句话与三句话

一句话：审的是记载，不是历史。

三句话：一座藏在林海里的被服厂，用一针一线支撑了前线；它被发现、被焚毁，只留下一处空下来的工作台；我们把每一句关于它的话，都接回能查的出处上。

观众先看完 88 秒的故事，再沿同一件事打开原文——看清哪些是记载、哪些是设计、哪些还没有答案。核查本身，就是纪念的方式。

二、要解决的问题

红色展陈长期在展示结论：抗联苦战十四年、杨靖宇壮烈殉国。这些结论成立，但支撑它们的推理链条通常被藏在展板背后。历史学的工作是「证据 → 推断 → 结论」，展陈往往只给最后一步。

数字人文项目常见另一种偏差：把「我检索过」写成「史料如此」，把「几家转引」算成「多方互证」。作品要处理的就是这两件事——把中间两步摊开，并把「不知道」当作一等公民。

被服厂是一个合适的切口：它足够具体（15 人、一台旧缝纫机、树皮染布），又有完整的因果链（建立 → 生产 → 告密 → 转移 → 留守者牺牲 → 遗址复建），并且公开材料足以支撑一条可核查的叙事。

四、核心机制：证据链与边界

4.1 四层结构

文档 → 原文片段 → 原子主张 → 章节 / 卷宗 / 图形

每层有稳定 ID，显示名不作外键。主故事的 8 章 10 条主张写在 data/curated/story_claims.json，每条带逐字引文与「记载 / 设计」边界；构建脚本校验引文能否在存档原文中逐字定位，不通过则构建失败。

4.2 日期支持关系按精度计算

一条记载被多家来源支撑，不等于每家都支持它的日期。作品对每条来源逐条判定六种状态：未载、明确相合、范围相容、范围不符、互斥、另一动作；另设「考订说明」（引文里出现的是被考订的错误值）与「起始年表述」两类豁免。

例：东北抗联教导旅成立一案，库内 5 条来源中只有 2 家明确记到「8 月」，2 家记的是「编成/改编」（与本条主张的「成立」不是同一动作），1 家未载。因此该案标注为「8 月（主张精度：月）→ 仅 2 家明确相合」，而不是「来源记载相合」。

4.3 月精度不冒充日

原文只写「6 月」时，系统不会补成「6 月 1 日」再与「7 月 12 日」算相差 41 天。两个日期精度不同时，结论是「不可比（精度不同）」——先对齐精度，再谈差多少。

4.4 数值裁决链

两组兵力分歧（抗联鼎盛 3 万 / 4.5 万；义勇军 30 万 / 50 万）给出裁决：采哪一口径、依据是什么、另一说如何处置、什么条件下可推翻。裁决状态分「已核」与「待核验编辑假说」——没有原文定位的口径解释被隔离为假说，不得当作事实陈述。

六、技术实现

6.1 形态与构建

纯静态前端，无框架、无后端、运行时不调用大模型 API。数据管线为 Python 离线脚本：

events.json → conflicts.py → build_cases.py → build_structures.py → build_web.py，另有 build_story.py 生成主故事主张集。

所有指标由脚本计算后注入页面，不手填；构建产物为 web/data.js、web/structures.js、web/cases.js、web/story.js。

6.2 3D 与 WebXR

  • Three.js r150（MIT，库文件随附许可头），66 座灯火与 33 座烽燧使用实例化渲染；流光粒子 284 条。
  • 场景状态与字幕同源：第 6 幕物资已转移、第 7 幕人物与布料移出画面（scene{workers, props}），画面状态可用 body[data-scene-workers] 断言。
  • WebXR：双目渲染、手柄指向选取、地面瞬移、世界空间证据卡；未用实体头显验收前不宣称真机效果。
  • 章节深链 ?factory=1&chapter=7，答辩可按需跳段。

6.3 可访问性

  • 2D 画布按内容包围盒动态计算（2124px），33 家来源与 66 条记载全部可达；提供「适应宽度 / 原尺寸」切换。
  • 悬停只做预览；点击或 Enter 打开固定详情，出处链接可点，Escape 关闭并还焦。
  • 手机端正文卡改底部抽屉、正文折叠 3 行可展开；概念图手机默认收起。
  • 尊重 prefers-reduced-motion：减少动态效果时不自动运镜，保留字幕与逐幕亮灯。

七、原创贡献与学生工作

本作品的原创性不在「用了什么技术」，而在把核查机制做成了可看、可点、可回放的产品结构：

  1. 证据模型：文档 → 引文 → 原子主张 → 章节/卷宗/图形四层，配稳定 ID 与边界标注（记载 / 设计 / 假说）。
  2. 逐精度比对规则：六态日期支持判定 + 两类豁免，解决「一家到日、几家到月被判成共识」的常见错误。
  3. 可审计的负证据：检索记录附原始页面快照与哈希，评委可点开核对抓取时刻的页面。
  4. 叙事与证据同源：主故事每幕的主张、引文、视觉边界写在同一份 JSON，3D 不硬编码正文。
  5. 空间化的承重结构：抽离来源后熄灭多少灯火由支撑关系实时计算，不是预设动画。

具体分工：策划与叙事结构、数据模型与统计口径、规则脚本、前端与 3D 场景整合、验收标准由学生完成；AI 辅助检索比对、代码编写与概念图生成，逐项记录于《AI 使用说明》。

八、研究局限

  • 无一手档案：66 条记载全部来自公开二手材料，A 类档案为 0。作品能证明「库内记载如何相合或分歧」，不能证明「历史事实如此」。
  • 来源独立性未判定：多家机构可能转引同一底本；本库只按机构归并计数，不做谱系考证。
  • 3D 为合成示意：程序化场景不是遗址扫描；房屋间数、院落布局、机器形制均标注为设计选型。
  • 读速与理解未做真人验证：88 秒 8 幕的阅读负荷需真实观众测试，当前只有设计判断。
  • 性能未做真机实测：中端核显与手机的帧率、头显的舒适度均待实测，现有结论仅来自桌面浏览器。

十、复核方式

在干净目录下依次运行：

python src/conflicts.py data/curated/events.json -o data/curated/conflicts.json
python src/build_cases.py
python src/build_structures.py
python src/build_web.py data/curated/events.json data/curated/conflicts.json
python src/build_story.py
python src/verify_quotes.py

期望结果：66 条事件、33 家机构、校验问题 0、主故事 10 条主张引文全部可对照。随后直接打开 web/index.html、web/dossier.html、web/sanctuary.html。

十一、结语

这座被服厂没有留下照片。我们知道的，是 15 个人、一台旧机器、树皮染出的黄绿色，和一间被烧掉的房子。

作品不替这些记载下结论，只把它们摊开：哪一句有出处，哪一句是推测，哪一句还没有答案。然后，把那个空下来的工作台留在画面里。

核查，是纪念的一种方式。
