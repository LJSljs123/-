# 《密营 · 燎原》—— 3D/WebGL 空间化视觉方案

> 一句话：**把 66 条结论变成雪原夜色里的 66 座密营灯火，把 16 个来源变成 16 座供给它们的烽燧；抽掉一个来源，就是一场夜袭。**

---

## 0. 为什么是这个，而不是别的

已经排除的方向：

| 方向 | 为什么不行 |
|---|---|
| 3D 力导向证据星系 | 把 2D 图加个 z 轴而已，评委见得更多 |
| 地图 3D 化 | "地图太 low"已被否定，且库里**不编造坐标** |
| 通用 WebGL 炫技（粒子海/背景） | 装饰不是论证，"展示结论"是 low 的根源 |

选定的方向：**让 3D 空间本身就是论证**。作品叫《密营》——东北抗联的密营，就是林海雪原里**看不见却真实存在**的据点。这个意象和数据完全同构：

- 密营 = 孤悬的证据（单源结论：微弱、摇曳、随时熄灭）
- 多源互证 = 几座密营遥相呼应的火光
- 来源 = 供给灯火的山头烽燧
- 抽掉来源 = 夜袭：断供、灯灭、雪崩
- 负证据 = 地图边缘未勘探的黑暗林区

**空间不是装饰，空间就是证据链本身。** 这才是"视觉炸"的正确姿势：评委被雪原夜景砸中的同时，看到的是崩塌率在眼前发生。

## 1. 场景五层结构（数据 → 空间映射）

```
第七层  天幕        时间轴 1931—1945 横贯天际，事件按年份排布
第六层  极光/夜空   纯氛围，体 shader，随交互强度变化
第五层  黑暗林区    负证据：未查领域的雾墙，边界随检索记录生长
第四层  16 座烽燧   来源节点：烽火台造型，火光强度 = 支撑面
第三层  光索网络    来源→结论的支撑边：流光粒子沿线流动
第二层  66 座密营   结论节点：灯火组（火堆+帐篷+光晕）
第一层  雪原地面    GPU 噪声地形 + 观察者视差雪
```

### 数据映射表（全部来自现有 data.js / structures.js，零新增数据）

| 数据 | 空间表达 |
|---|---|
| `sources[].count`（支撑数） | 烽燧火光强度 + 体积 |
| `sources[].exclusive`（独占数） | 烽燧顶部的**红旗警戒灯**，独占越多灯越红 |
| `edges`（支撑关系） | 烽燧→密营的流光索，粒子沿曲线流动 |
| 结论 `sources` 数量 | 密营篝火大小：1 源=微弱残火，多源=熊熊营火 |
| 结论 `event_type` | 火光色温（牺牲=冷白偏蓝，战斗=暖橙，会议=青色…） |
| 单源结论 | 火焰随机摇曳（噪声扰动），**脆弱感可见** |
| `date_variants` 冲突对 | 两座密营之间跳动的**红色电弧** |
| 检索深度 deep/shallow | 烽燧投照到地面的探照扇面宽窄 |
| `not_searched` | 黑暗林区边缘的雾墙，hover 显示"未查：…" |

## 2. "炸点"清单（评委记忆点）

按演示顺序，每个炸点都要能在 10 秒内被手机录像拍清楚：

1. **开场运镜**：黑屏 → 一片雪花落在镜头上 → 相机从高空俯冲穿越云层 → 雪原展开，66 座灯火渐次点亮（按 1931→1945 时间顺序，如同燎原）→ 天幕年份字幕依次亮起。8 秒，零交互。
2. **证据流光**：拉近任意烽燧，可见光索上粒子**沿着曲线流向密营**——证据在"供给"。悬停任意光索显示：这条边支撑哪条结论、来源引文。
3. **夜袭模拟（核心炸点）**：点击任意烽燧 → 全场变暗、警报红灯亮起 → 相机震屏 → 该烽燧的所有光索**断裂粒子化**（崩解成雪烬）→ 其支撑的密营火焰**依次熄灭**（顺序按置信度）→ 熄灭的密营坍塌成雪堆 → 结算面板浮现："抽掉《辽宁日报》：37/66 失去依据，库残存 44%"。
4. **复活**：再点一次，烽燧重建，灯火按依赖顺序重新点燃——让评委看清**哪些灯是靠它活着的**。
5. **电弧**：镜头掠过多伦那对密营，可见 6 月/7 月 12 日的红色电弧在两团火之间跳动——**日期分歧第一次有了空间形态**。
6. **雾墙**：飞向地图边缘，黑暗林区，雾中隐约有"未勘探"轮廓——负证据的可视化：**你看得见边界在哪，而不是假装没有边界**。
7. **尾声运镜**：一键"十四年"模式：相机沿时间轴横扫，密营灯火随年份明灭——1941 年后大片熄灭（代价可视化），但仍有火种坚持到 1945。

## 3. 交互与信息层（不牺牲严谨性）

3D 只负责"炸"，所有考据细节仍走 DOM 浮层（复用现有 tooltip/卷宗逻辑，禁用 WebGL 内嵌文字的逼仄感）：

- **悬停**：密营 → 结论卡（引文、来源、检索记录、单源警示）；烽燧 → 来源卡（count/exclusive/崩塌率）。
- **点击密营**：右侧滑出卷宗面板（dossier 数据全量），相机轻推近景。
- **抽离模式**：可连续抽多个来源（多来源联合抽离，对应计划 10/21），结算面板实时重算。
- **2D/3D 双视图**：index.html（SVG 承重结构，评审深究用）与 sanctuary.html（3D 主视觉）共享同一 data.js，右上角一键切换。**答辩放 3D，答辩后评委自己看 2D。**

## 4. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | **Three.js r160+**（CDN，ES Modules） | 生态最全、体积可控、EffectComposer 后期链成熟 |
| 后期 | UnrealBloom + 自写雪雾 pass | Bloom 是灯火质感的命；SSAO 移动端砍掉 |
| 地形 | 自写 vertex shader 噪声（simplex） | 不引 heightmap 文件，纯程序化 |
| 密营/烽燧 | **InstancedMesh**（66+16 实例） | 单 draw call；火焰用 Points + 自定义 shader |
| 流光索 | QuadraticBezierCurve3 + 粒子沿线 | 数百条边一个 Points 对象全搞定 |
| 文字标签 | **Canvas 贴图 Sprite**（不用 troika） | 中文 SDF 字体文件 3MB+，Canvas 方案零依赖、离屏渲染一次 |
| 相机 | 自写轨道 + 关键帧运镜系统 | 不引 tween 库，自写 40 行补间够用 |
| 数据 | 复用 data.js / structures.js | 前端纯静态铁律不破 |
| 崩塌物理 | 自写简化粒子（不引物理引擎） | 熄灭坍塌是编排好的动画序列，不需要真物理 |

**不用 babylon 的理由**：体积大、中文资料少、本场景不需要其节点材质编辑器。**不引 React Three Fiber**：项目是零构建纯静态，引入 JSX 构建链违背工程约定。

## 5. 性能预算与降级

- 粒子总量 < 150k（雪 80k + 流光 40k + 火焰 20k + 爆裂 10k），中端核显 60fps
- draw call 目标 < 60：地形 1 + 天空 1 + instanced 密营 3 + instanced 烽燧 2 + 光索 Points 1 + 雪 1 + 火焰 1 + bloom 链 ~8
- 三档画质：高（全特效）/ 中（雪减半、无 SSAO）/ 低（静态雪贴图、无 bloom，保交互）
- 帧率自适应：连续 3 秒 < 45fps 自动降档，UI 提示
- 无 WebGL2 的设备：自动跳转 2D 视图并提示

## 8. 需要你确认的两件事

1. **《密营 · 燎原》这个概念方向**——夜袭熄灯作为核心炸点，还是希望核心炸点换成别的（比如时间轴燎原模式）？
2. **音效**：要不要风声/火声环境音（Web Audio 合成，默认关、按键开）？答辩现场通常静音，但视频里加上会强很多。

确认后我直接开工 10/18 上午的场景骨架。
