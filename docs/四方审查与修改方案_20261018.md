## 一、评委视角：五个决定名次的问题

### 1.1 第一印象是"数据工具"，不是"作品"（最严重）

`web/index.html` 是 2D 承重结构——66 根芦苇、33 根柱子、一堆数字。评委点开链接的第一眼看到的是**仪表盘**。

深审报告已经指出同类获奖作品是故事型（《前世筑梦·今朝铸魂》《圆梦屯字镇》）。现在的入口顺序把最强的资产（88 秒被服厂故事）藏在二级页面。

**这不是审美问题，是判断顺序问题**：评委平均给一个作品 30–60 秒，前 10 秒决定他是否认真看。

**改法**：把 `sanctuary.html?factory=1&chapter=1` 做成默认入口（或加一个 3 秒过场：先出"记载相差一个月"三行字，再进故事）。2D 保留为"深究"入口，但不再是第一屏。

**工作量**：2 小时。**收益**：最大。

### 1.2 视频没录 = 材料缺一半

官方要求「评审视频或 PPT 至少一项」。脚本已到逐秒，但**没录**。这是唯一可能直接失分的项——不是内容问题，是交付问题。

**改法**：明天上午先录一版（哪怕不完美），有备份再优化。PPT 建议补一份 8 页（视频挂了还有 PPT）。

**工作量**：录制 3 小时 + 后期 3 小时；PPT 2 小时。

### 1.3 "0 条一手档案"出现在页面上，但没有被"解释"

作品诚实地写着 A 类档案 0/66。诚实是对的，但**评委看到会想：那你凭什么参赛？**

现在没有任何地方回答这个问题。需要在 2D 页脚或卷宗页首加一句：

> 本库不收档案原件，收的是**公开记载之间的对位关系**。0 条一手档案不是缺陷，是范围声明——它决定了我们只谈"记载如何相合或分歧"，不谈"历史事实如此"。

**工作量**：30 分钟。**收益**：把一个减分项变成方法论声明。

### 1.4 缺一个"30 秒能讲完"的电梯陈述

现在 README 顶部没有一句话版本。答辩第一问通常是"用一句话说你在做什么"。

**改法**：README 顶部加三行（一句话 / 三句话 / 一个类比）。

**工作量**：20 分钟。

### 1.5 答辩问题没有准备答案

深审给了 10 个必问题（核查机制差异、出处范围、多机构≠互证、四间/四栋、年份相合、抽离影响、制作过程、第三方素材、手机与头显验证、失败恢复），但**没有答案文本**。

**改法**：写 `docs/答辩问答.md`，每题 3–5 句，含"如果被追问"的第二层。

**工作量**：2 小时。**收益**：答辩 10 分里能拿 8 分以上。

## 二、3D / 前端专家视角：八个技术问题

### 2.1 相机推不近——第 3 幕的承诺是假的（P0）

**证据**：
- 第 3 幕文案：「近看针杆、布料与针脚」
- `story_claims.json` 第 3 幕 `camera: [0.08, 1.48, 10, ...]`（radius = 10）
- `sanctuary.js:936` 与 `:1004`：`radius = Math.max(factoryMode ? 10 : 22, ...)` —— **最小半径被锁死在 10**

相机 FOV 55°，距离 10 米时画面高度 = 2×10×tan(27.5°) ≈ **10.4 米**。缝纫机针杆尺寸约 0.1 米 → 占画面高度 **不到 1%**。观众看到的是一个模糊的桌面，不是针杆。

这是全项目最典型的"文案承诺、代码做不到"。

**改法**：
1. `Math.max(factoryMode ? 10 : 22, ...)` → `Math.max(factoryMode ? 2.2 : 22, ...)`（两处：wheel 与 pinch）
2. 第 3 幕 radius 10 → 2.6，target 对准针杆位置
3. **同时**把第 3 幕的视觉焦点从"整台机器"改成"针杆 + 手 + 布"的局部（否则近了只能看到粗糙几何）

**验收**：`?factory=1&chapter=3` 截图里针杆、手指、布面三者同框且可辨认。

### 2.2 缝制的手不在布上（P0）

**证据**（几何计算，含旋转）：
- 坐姿工人组原点 `(-0.8, 0, 0.45)`，`turn = π/2` → 局部 (x,y,z) 映射到世界 (z, y, -x)
- 工作手局部 `(0.68±0.12, 1.52, 1.48)` → 世界 `(0.68, 1.52, -0.23)`
- 布堆中心 `(-0.4, 1.50, -0.05)`，尺寸 `1.2 × 0.18 × 0.8` → x ∈ [-1.0, 0.2]

**手在 x=0.56~0.80，布堆右缘只到 x=0.2** —— 手离布 0.36 米，在空气里做缝纫动作。而布堆顶面 1.59 高于手 1.52，手即使移过去也会穿模。

**改法**：
1. 布堆移到缝纫机针杆旁（机器在 `(0.3, -0.25)`，布堆移到 `(0.45, 1.50, -0.18)`，尺寸缩到 0.7×0.14×0.5）
2. 手位抬到布面之上：`handY` 1.52 → 1.60，`handZ` 1.48 → 1.55（世界 x≈0.75）
3. 手指尖落点贴近布面 0.02

**验收**：第 3 幕近景截图，手指与布面接触处无可见缝隙、无穿插。

### 2.3 第 2 幕"15 名成员"画面只有 2 个人（P0）

**证据**：文案「被服厂由 15 人组成」；场景 `buildWorker` 调用 2 次；文案自己补了一句"不按比例再现全体成员"。

自我防御的括号解决不了视觉落差——观众听到"15 人"，看到 2 人。

**改法（二选一）**：
- **A（推荐，成本低）**：把第 2 幕镜头改成**手部特写**（多双手在布上），文案改为「至少 13 双女工的手」；用 3–4 个只露前臂与手的局部模型，避免"全身人只有两个"的破绽
- **B**：加 4–6 个远景虚化人形（低模剪影），画面读作"一群人在工作"

**验收**：截图里不再出现"两个完整人 + 文案说 15 人"的组合。

### 2.4 纹理 256px，近景必糊（P1，与 2.1 联动）

**证据**：`weaveTexture()` / `timberTexture()` 均 `canvas.width = 256`。

一旦相机能推到 2.6 米，256px 纹理在近景会明显拉花。**2.1 与 2.4 必须一起改**，否则推近反而更差。

**改法**：布与木两种纹理提到 512，并加一层程序化细节（噪声 + 纤维方向），近景时用 `texture.anisotropy = renderer.capabilities.getMaxAnisotropy()`。

**工作量**：2 小时。

### 2.5 单文件 95KB，状态耦合高（P1，临期只做最小隔离）

**证据**：`sanctuary.js` 95KB，全局可变状态包括 `mode / factoryMode / tour / factoryTour / factoryCameraGoal / sceneFade / claimsOpen / pinned` 等，互相依赖。

风险不是"不优雅"，是**回归**：改一处镜头逻辑可能影响风雪试验的结算。

**临期建议**：不重构，只做两件低风险的事：
1. 把 `mode` 的所有合法值集中成一个常量表 + 断言（非法值直接抛诊断号）
2. 给 `renderFactoryChapter` / `startStorm` 各加一条"进入前先 reset"的断言

**明确不建议**：临期拆模块。收益 < 风险。

### 2.6 性能没有真机数据（P1）

66 灯火 instanced + 33 烽燧 + 258 棵树实例 + 284 粒子。桌面 headless（SwiftShader）能跑，但**没有 GPU 真机帧率**。

**改法**：`docs/性能实测.md`，记录三档（桌面核显 / 手机 / 关闭 3D），用 `requestAnimationFrame` 采样 10 秒算 p50/p95。没有数据就不要在材料里写"流畅"。

### 2.7 2D 首屏信息密度过高（P1）

66 个节点 + 33 根柱子 + 15 个年份刻度，默认视图下标签重叠概率高。虽然已做动态 viewBox，但**"全部可见"不等于"看得清"**。

**改法**：加一个"聚焦模式"——点击年份刻度只显示该年，其余淡化到 15% 透明度。成本 1.5 小时，收益是评委能真的读图。

### 2.8 错误恢复只做了数据缺失（P2）

已有 `M-DATA-01`。还缺：WebGL context lost、纹理加载失败、字体缺失。WebGL 丢失在评委的旧笔记本上**真的会发生**。

**改法**：监听 `webglcontextlost`，显示"图形上下文丢失，请刷新；2D 视图不受影响"并提供跳转。

## 三、叙事视角：五个文本问题

### 3.1 八幕是"说明文"，不是"故事"（P0）

现在第 1 幕开场：「为解决抗联部队物资补给，第三军决定在小西林河上游密林深处的老道庙沟、娘娘宫一线建立被服厂。」

这是**地方志句式**。观众第一句听到的是行政决策，不是人的处境。

**改法**：开场从"物"切入，不从"决定"切入。例：

> 一件棉衣，在零下四十度的林子里，能决定一个人能不能活到明天。
> 1936 年 8 月，15 个人走进小西林河上游的密林，去解决这件事。

事实没变（15 人、1936 年 8 月、小西林河上游、物资补给），但**先给处境，再给事实**。

### 3.2 有名字的人一个都没进画面（P0）

原文里有：**金伯文**（党支部书记）、**陈静山**（厂长）、**阎把头**（报信者）、**"小把头"**（留守牺牲者）。

现在这些名字只出现在 claim 的正文里，**故事旁白一次都没提**。而"小把头"是全片最有戏剧性的人物——他因为没来得及撤走而牺牲。

**改法**：第 2 幕点出「党支部书记金伯文、厂长陈静山」；第 6 幕点出「阎把头把消息告诉了陈静山」；第 7 幕用「留守的'小把头'」并停顿。**不虚构任何对白与心理**，只把已有名字放到该在的位置。

**收益**：从"一群无名的人"变成"几个有名字的人"——这是叙事的基本功，也是评审最容易被击中的点。

### 3.3 第 5 幕"联席会议"是断的（P1）

文案说"在被服厂密营召开联席会议，成立北满临时省委"，但画面只有工作台，且自己声明"不重建会议现场"。

观众会困惑：刚才说开会，怎么还是缝衣服？

**改法**：把这一幕的功能改成"**同一张桌子，换了一件事**"——镜头从布移到桌上的纸与笔（有记载的"联席会议"事实），文案：「针线之外，这张桌子还开过一次会」。不需要重建会场。

### 3.4 结尾数据句的位置不对（P1）

第 8 幕把「66 条 / 55 条 / 0 条一手档案」放在故事结尾。**情感刚落，立刻上统计**，会泄气。

**改法**：数据句移到落版**之后**作为独立一屏（黑底白字），或者干脆只在 2D 页出现。故事结尾只留「核查，是纪念的一种方式」。

### 3.5 88 秒的阅读负荷（P1）

每幕 11 秒，正文 44–92 字。按 4.5 字/秒，92 字需要 20 秒——**读不完**。

**改法**：正文压到 ≤55 字/幕；长文全部放进「本章主张与引文」面板（已有）。
