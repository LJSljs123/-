# 史料采集任务清单

> 目的：把 80–120 条事件凑齐，且每条都能追溯。
> 原则：**我不替你写历史。** 下面只给"去查什么、去哪查"，具体日期、伤亡、原文由你从史料里抄。

## 一、总体思路

15 个主干节点 × 每个节点 5–8 条子事件 = 80–120 条。

不要一上来就铺全国，先选**一个片区**做深：建议从辽宁东部（本溪—桓仁—宽甸）或吉林东南（磐石—通化—靖宇）入手，这两片的史料最集中，纪念馆也最多。

## 三、每条事件要录什么

打开 `data/curated/史料录入模板.xlsx`，一行一条。红色表头必填。

最关键的是**原文摘录**那一列：照抄，不改写。这一列决定作品能不能过"原创性与真实性"审核。

## 四、冲突组怎么建

同一件事，两本书写得不一样，就建一个冲突组。

例如杨靖宇牺牲的具体时间、牺牲前几天的行踪，不同著作记载有差异。你录两行、id 不同、`冲突组` 填同一个编号，系统会自动比对并在地图上用金边标出。

**不要自己判断哪个对。** 保留分歧，这本身就是作品的内容。

## 五、数据量不够时的降级

- 只做 40 条：缩到"杨靖宇最后 100 天"这一个切口，时间从 1939 年 12 月到 1940 年 2 月。切口小、密度高、情感集中，比铺开 15 个节点更有力。
- 只做 20 条：做"一个县的抗联记忆"，比如靖宇县或林口县，全部事件限定在该县境内。

## 六、录完之后

```bash
python src/import_excel.py                          # Excel → events.json
python src/conflicts.py data/curated/events.json -o data/curated/conflicts.json
python src/build_web.py data/curated/events.json data/curated/conflicts.json
```

三步跑完，页面自动更新。校验不通过的条目会列出来，不会进库。
